# Velvet Radio — расширение Chrome

Перед добавлением, изменением или проверкой радиостанций, потоков, качеств, зеркал, названий песен и логотипов
обязательно следуй правилам из файла ниже. Пользователю не нужно пересказывать их заново.

@ADDING-STATIONS.md

Коротко:
- Битрейт на кнопке — заявленный (замер не нужен, решение Jack 2026-10-12), но поток обязательно проверять на живое аудио (не заглушка).
- Кнопки качества — заявленные ≥128 kbps (максимум три, цель 128/256/320); всё ниже 128 — скрытая страховка; **64 kbps** на кнопки никогда; скрытым запасом `hid(64)` — только в самом крайнем случае, когда иначе никак.
- У каждого качества должны быть зеркала и резерв; без выдумок: нет источника песен или потока — честно сообщить.
- Весь код внутри расширения, без remote code.
- Проверки только скрытые и без звука (пользователь может играть в игры); в конце убить тестовые процессы.

## Выпуск обновления: «Что нового» обязателен (решение Jack 2026-10-25, действует во ВСЕХ будущих обновлениях)
Тот, кто просто обновился, должен узнать, что изменилось: короткие карточки «Что нового» в стиле и с анимацией тура (тот же движок `ui/tour.js`: подсветка элементов, «Далее» / «Назад» / «Пропустить», сохранение прогресса, один раз на версию). Полный тур им не показывать.
Перед каждым выпуском (любая новая версия в `manifest.json`):
1. Переписать `WHATS_NEW_STEPS` в `ui/tour.js` под изменения именно этой версии (3–6 карточек, цели на реальные элементы окна, `alt` как запас) и тексты `wn_<id>_t` / `wn_<id>_d` + `wnDone` на русском **и** английском в `i18n.js`. Учитывать всё новое и изменённое в `CHANGELOG.md`; старые карточки убрать.
2. Поставить эту версию в `WHATS_NEW_FOR` (`lifecycle.js`). Без этого `tools/build.py` не соберёт пакет (только для выпуска без видимых изменений: `NO_WHATS_NEW=1`).
3. Прогнать `node tools/test-update.mjs` (ставит опубликованный предыдущий пакет, подменяет файлы новой сборкой, проверяет «Что нового», сохранение данных, один показ) и положить в `store-upload/0-пакет/` пакет прежней версии для следующего теста обновления.
4. Дать Jack проверить вручную до отправки в магазин: `node tools/update-demo.mjs prepare` → «Загрузить распакованное» → `apply` → «Обновить» на карточке расширения (команды запускать из папки проекта или с полным путём).
5. Разрешения в `manifest.json` не менять без явного согласия Jack (иначе Chrome отключит расширение у пользователей). Сверять с предыдущим пакетом.
