# Velvet Radio — правила добавления и изменения станций

Это обязательные правила. Они выросли из реальной работы над расширением, поэтому каждое что-то предотвращает.
Перед добавлением или правкой станции читай этот документ целиком и делай всё по шагам. Не пропускай проверки.

## 0. Главные принципы

1. **Битрейт на кнопке — заявленный, замер не нужен (решение Jack от 2026-10-12).** Берём цифру из официального плеера, адреса потока, каталога (radio-browser) или `icy-br`.
   Мы знаем, что название потока может врать (`europaplus320.mp3` = 128, у Record «320» — AAC 96), и принимаем это: три кнопки качества важнее точности цифры.
   **Но сам поток проверяем всегда:** он должен реально отвечать аудио (а не заглушкой или 404), играть и иметь нужный кодек. Старые замеры в каталоге остаются как есть.
   **Качество 64 kbps** на кнопки не выносим никогда. Как скрытая страховка `hid(64, …)` оно допустимо **только в самом крайнем случае**, когда иначе никак (например, у станции вообще нет ничего выше). Если есть выбор, 64 не берём.
2. **Ничего не выдумывать.** Нет источника названий песен — песни не показываем. Нет потока 256 — кнопки 256 нет.
   Если что-то не нашлось, честно сказать пользователю, где искал.
3. **Стабильность важнее громкого числа.** У каждого качества должны быть резервы (шаг 4), у каждой станции — страховочное качество ниже.
4. **Никакого чужого кода.** Весь JavaScript лежит внутри расширения (remote code запрещён). Скачиваем только данные: потоки и JSON.
   Библиотеки только копией в `vendor/`. Нельзя `eval`, `new Function`, `<script src="https://…">`, нельзя ослаблять CSP.
5. **Тесты — тихо.** Пользователь может играть в игру. Только скрытый браузер, без звука, без окон (шаг 9).

## 1. Где что лежит

| Файл | Что в нём |
|---|---|
| `stations/<страна>.js` | Каталог станций страны (`ru.js`, `us.js`, `gb.js`…): названия, жанры, качества, потоки, зеркала. Единственное место правды о станциях. Для России несколько файлов `ru*.js` |
| `stations.js` | **Генерируется** из `stations/*.js`: `node tools/gen-catalog.mjs`. Руками не править. После добавления или удаления файла страны запускать заново |
| `stations/genres.js`, `stations/countries.js` | Ключи жанров (ru/en) и список стран вкладки «Страны» (порядок, псевдонимы для поиска) |
| `flags/<cc>.svg` | Флаг страны (копия открытой библиотеки flag-icons, MIT). Для новой страны — флаг сюда и строка в `stations/countries.js` |
| `i18n.js` | Тексты интерфейса на русском и английском; жанры и названия стран берутся автоматически |
| `nowplaying.js` | Источники «что играет сейчас» по станциям |
| `manifest.json` | `host_permissions` для каждого сайта, откуда берём названия песен |
| `logos/<id>.png` | Логотип станции 128×128 |
| `offscreen.js` | Движок воспроизведения (буфер, зеркала, переподключение, визуализатор). Без теста не менять |
| `popup.js / popup.css` | Окно расширения. Список строится из `stations.js` автоматически |

Если станцию добавить в файл страны и перегенерировать `stations.js`, список, кнопки качества, перетаскивание, «следующая/предыдущая», фильтр по жанрам, поиск и горячие клавиши подхватят её сами. Названия песен у новых станций обычно не будет: для них нужен новый хост в `host_permissions`, а новые разрешения нельзя (решение Jack: проверка магазина и повторное согласие у пользователей). Исключение — источник с CORS или уже разрешённый хост.

## 2. Поиск и замер потоков

**Где искать потоки** (по убыванию надёжности):
1. Официальный плеер станции: код плеера, JSON-конфиги, `window.streams`, HLS master-плейлисты (смотри `BANDWIDTH` всех вариантов).
2. Серверы группы станций. Часто **у одной группы одинаковые адреса**: `*.hostingradio.ru`, `*.streamr.ru`, `*.emgsound.ru`, `*.mediacdn.ru`.
   Перебирай имена точек: `{станция}{64|96|128|192|256|320}.mp3|.aacp`, `{станция}-256`, `/radio`, `/fm`.
3. **Исходные (origin) серверы** с высоким битрейтом, куда официальный плеер не ссылается. Так нашлись настоящие 320 у Europa Plus, Ретро, Радио 7, Дорожного (`europaplussrc.hostingradio.ru:8014`) и Record (`recordsrc.hostingradio.ru:9010/rr_main`).
4. Страницы статуса Icecast (`/status-json.xsl`, `/status.xsl`): там перечислены все точки с битрейтами.
5. Каталоги и списки: radio-browser.info API, плейлисты на GitHub.
6. Вариант HLS: посмотри скрытые варианты (`/192/`, `/128/`), их нет в master-плейлисте.

**Замер битрейта (по желанию, не обязателен).** Если очень хочется уточнить цифру: скачай поток, отбрось первые 4 секунды (сервер выдаёт запас буфера пачкой), потом считай байты 15 секунд.
Для HLS: скачать 3 последовательных сегмента, размер × 8 / длительность. Допуск ±10% (VBR). Скрипт:

```python
import urllib.request, time
def kbps(url, secs=20):
    r = urllib.request.urlopen(urllib.request.Request(url, headers={'User-Agent': 'Mozilla/5.0 Chrome/130', 'Origin': 'chrome-extension://x'}), timeout=10)
    t0 = time.time(); t1 = None; n = 0
    while time.time() - t0 < secs:
        b = r.read(2048)
        if not b: break
        if time.time() - t0 >= 4:
            if t1 is None: t1 = time.time()
            else: n += len(b)
    return round(n * 8 / (time.time() - t1) / 1000), r.headers.get('content-type'), r.headers.get('access-control-allow-origin')
```

Для каждого потока записывай: **kbps, кодек (MP3/AAC), CORS** (`Access-Control-Allow-Origin: *` или эхо `Origin`).
Без CORS поток играет, но визуализатора у станции не будет (допустимо, дальше всё обработается само).

**Ловушки, на которые уже наступали**
- Несуществующий поддомен `*.hostingradio.ru` всё равно открывается (сервер-заглушка). Адрес «разрешился» не значит «существует»: проверяй, что вернулся аудиопоток.
- Региональные эфиры (`emgregion…moscow.*`, `maximum-omsk` и т.п.) — не зеркала: у них своя реклама и новости. Допустимы как отдельное качество только с пометкой `note` или как последний резерв.
- Серверы `src` и `origin` не рекламируются. Они могут закрыться без предупреждения. Поэтому у такого качества обязательно оставляем обычный 128 и HLS как запас.
- Сторонние ретрансляторы местных станций (Уфа, Брянск и т.д.) не берём: чаще всего это перекодировка 128 в «256».
- Wikimedia и некоторые сайты отдают 429 при частых запросах — делай паузы.

## 3. Какие качества показывать

- На кнопках **заявленные ≥ 128 kbps**, максимум три. Подпись = заявленное число (112, 128, 192, 256, 320). Цель: для каждой станции найти три самых высоких качества (желательно 128 / 256 / 320), если такие потоки существуют и играют; не выдумываем потоки, которых нет.
- **64 kbps на кнопки не выносим никогда**, скрытым `hid(64)` — только в самом крайнем случае (поправка Jack от 2026-10-12). 96 kbps (обычно AAC) кнопкой — только если выше ничего нет (Record, Comedy).
- Всё, что ниже 128, добавляем как скрытое качество `hid(...)`: оно нужно только как автоматическая страховка при падении.
- Если на сайте станции качество называется иначе, чем реальное, пиши подсказку `note` (как у Record: «AAC 96 kbps — на сайте Record это поток „320“»).
- По умолчанию играет самое высокое качество.

## 4. Резервные потоки (зеркала)

- В каждом качестве `urls: [основной, зеркало 1, зеркало 2, …]`. Порядок = порядок попыток.
- **Настоящее зеркало** — другой хост с тем же содержимым (проверка: разные IP через DNS, одинаковая песня в метаданных).
  Один и тот же IP под другим именем (`nashe.streamr.ru` = `nashe1`) зеркалом **не считается**.
- Вариант того же хоста по `http`/`https` добавляем в конец: он спасает от проблем с TLS, но не от падения сервера.
- Внутри одного качества можно смешивать обычные потоки и HLS: `{ url, hls: true }`.
- Зеркало должно реально отдавать аудиопоток (проверка из шага 2: аудио, а не заглушка и не просто «200»); замер битрейта не нужен.
- Если зеркала нет, это нормально: сработают повторы и автоматическое понижение качества (см. ниже, как работает движок).

## 5. Названия песен (`nowplaying.js`)

1. Ищи **тот же источник, что использует официальный сайт станции** (сетевые вызовы плеера, код сайта). Не выдумывай адреса.
2. Группы станций часто делят один бэкенд: `meta.hostingradio.ru/emg/{код}/history` (Europa Plus Media), `meta.fmgid.com/stations/{slug}/current.json` (Gazprom-Media), `{сайт}/api/n/current` (Русское, DFM, Maximum, Хит FM, Monte Carlo), `hls-01-gpm.hostingradio.ru/{имя}/metadata.json`.
3. Запасной вариант: метаданные прямо в потоке (ICY, заголовок `Icy-MetaData: 1`). Работает не везде.
4. Фильтруй мусор: реклама, джинглы, «Реклама», `type != 3`, пустые артист и название, `***`. В этих случаях возвращай `null`: расширение оставит прошлую песню.
5. Добавь функцию в `SOURCES` (`nowplaying.js`) и **хост в `host_permissions`** (`manifest.json`).
6. Нет рабочего источника → станция без названия песни. Это нормально и честно (так сейчас у Шансона, Маяка, Business FM, Вести FM, Звезды).
7. Проверь вживую: запрос возвращает настоящую песню, а не прошлую.

## 6. Логотип

- Берём с официального сайта: `apple-touch-icon`, `og:image`, иконки приложения, логотип из шапки сайта; запасной вариант — страница станции в Википедии.
- SVG превращаем в PNG через Chrome headless (в системе нет cairo).
- Итог: `logos/<id>.png`, квадрат **128×128**. Квадратные с собственным фоном ставим как есть; прозрачные и широкие кладём на плитку (белую, для светлых логотипов — тёмную) с отступом.
- Смотри глазами (контрольный лист): ничего не обрезано, текст читается, это именно логотип, а не рекламная картинка.

## 7. Как оформить станцию в `stations/<страна>.js`

```js
import { q, hid, hls } from './lib.js';
export default [
  { id: 'us-example', name: 'Официальное Название', country: 'US', genre: 'hiphop', mark: 'Эк', hue: 200,
    alt: 'Эгзампл радио, транслитерация для поиска',            // необязательно
    qualities: [
      hid(96, 'https://host/example96.aacp'),                       // скрытая страховка
      q(128, 'https://host/example128.mp3', 'https://mirror/example128.mp3'),
      q(256, 'https://host/example256.mp3', 'https://mirror2/example256.mp3'),
      hls(320, 'https://host/example/master.m3u8'),                 // HLS только если нужен
    ] },
];
```

- `id` латиницей, строчными, без пробелов, уникальный; у иностранных станций префикс страны (`us-`, `gb-`). **Id существующих российских станций не менять:** на них держатся избранное и порядок пользователей. `name` — **официальное название** (не «Record», а «Radio Record»); для нелатинских названий в `alt` добавь латиницу и русскую транслитерацию (по ним ищет поиск); `mark` — 1–2 буквы на случай, если логотип не загрузится; `hue` — оттенок 0–360.
- `country` — код страны (`RU`, `US`, `GB`…), он должен быть в `stations/countries.js` (кроме `RU`).
- `genre` — ключ из `stations/genres.js` (`pop`, `hiphop`, `oldschool`, `country`…), для разового жанра `{ ru: '…', en: '…' }`.
- **Состав жанров у каждой страны свой**, по тому, что там реально популярно, примерно по 2 станции на жанр (а не десять поп-станций). У США и Великобритании станций больше.
- `qualities` по возрастанию kbps. Качества `hid()` не показываются кнопкой. Минимум одно видимое качество.
- После правки: `node tools/gen-catalog.mjs`, потом `node tools/check-catalog.mjs --live`.

## 8. Как работает движок (чтобы не сломать)

`offscreen.js` играет звук в скрытом документе. Порядок при запуске: выбранное качество → все его адреса (два круга) → качество ниже (по одному кругу) → «Станция недоступна» + кнопка «Повторить».
Перед стартом набирается запас звука 4 секунды (`PREBUFFER_S`), иначе любая просадка даёт заикание. Сторож перезапускает поток, если звук завис на 9 секунд.
Визуализатор включается только если сервер разрешает CORS; звук идёт через `AudioContext` в режиме `latencyHint: 'playback'`.
**Эти константы и логику не менять без теста на заикание** (шаг 9).

## 9. Проверки перед «готово» (обязательно)

Всё делать **скрыто и без звука**: Playwright + Chromium из `ms-playwright`, запуск `--headless=new --mute-audio`, расширение через `--load-extension`. Никаких видимых окон, фокуса и звуков. Пользователь может играть.

0. **Инструменты** (папка `tools/`, в расширение не входят; `cd tools && npm install` один раз):
   `node tools/probe.mjs <url>…` — живой ли поток, кодек, CORS; `node tools/probe.mjs --rb "название" --cc RU` — кандидаты из radio-browser;
   `node tools/check-catalog.mjs [--live]` — проверка схемы каталога и (с `--live`) всех адресов;
   `node tools/test-playback.mjs [--ids a,b] [--mode full] [--scenario mirror|tier|all]` — скрытый тест воспроизведения;
   `node tools/ui-shots.mjs <папка>` — скриншоты окна и ошибки консоли; `python tools/make-logo.py <id> <файл|url>`, `python tools/logo-sheet.py out.png <id>…` — логотипы.
1. `node --check` для изменённых `.js`; `manifest.json` читается как JSON; **набор `permissions` и `host_permissions` в `manifest.json` не изменился** (нельзя добавлять разрешения).
2. Станция играет на **каждом** качестве (`status: playing`, нужный `kbps`), 40–90 секунд без заиканий (`stalls = 0`). Для каталога из сотен станций: быстрый режим (15 с, все) плюс полный (60 с) на новых и на всём, что затронуло движок. Из-за лимитов серверов не запускай больше 3 браузеров и не гоняй тест одновременно с массовой проверкой адресов: ложные «не подключилось».
3. Визуализатор: `viz: true` либо осознанно отсутствует (нет CORS).
4. Резервы: сломать первый адрес в копии каталога, убедиться, что переключилось на зеркало; сломать всё качество, убедиться, что упало на меньшее; сломать всё, убедиться, что показана ошибка.
5. Название песни приходит (либо источника нет, и это записано).
6. Логотип смотрим глазами; окно в светлой и тёмной теме, длинное название не ломает строку.
7. **В конце убить тестовые процессы** (`ms-playwright`), убедиться, что их 0.
8. Пользователю: что сделано, как проверить самому, и честно, что **не** удалось найти.

## 10. Чего не делать

- Не считать название потока, `icy-name`, имя файла доказательством, что поток живой: всегда проверять, что идёт аудио.
- Не добавлять поток, который не проверен на живой аудиоответ (замер битрейта не обязателен).
- Не выносить 64 kbps на кнопки; скрытое `hid(64)` — только в крайнем случае, когда иначе никак.
- Не добавлять сторонние ретрансляторы и неофициальные эфиры без пометки.
- Не подключать код из интернета (CDN, `eval`, удалённые скрипты).
- Не запускать видимые окна и звук во время проверок.
- Не менять буфер/таймауты движка без замера заиканий.
